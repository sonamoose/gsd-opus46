Create `get-shit-done/references/brownfield-detection.md` as a reference document containing the complete mode detection logic specification.

**Document structure:**

### 1. Overview Section
- Purpose: Deterministic mode detection for `/gsd:new-project` command
- Outputs: MODE (greenfield | scaffolded | brownfield), PRIMARY_LANG, HAS_CODEBASE_MAP
- Design: Zero LLM tokens, pure Bash, multi-signal scoring
- Integration point: Will be embedded in `commands/gsd/new-project.md` Phase 1-2 (Phase 4 of this project)

### 2. Signal Categories (4 categories)

**Signal 1: Code Files** — Count non-config, non-generated source files
- File extensions (20+) grouped by language family:
  - **Web/Backend:** `.ts`, `.tsx`, `.js`, `.jsx`, `.py`, `.rb`, `.php`, `.go`, `.rs`, `.ex`, `.exs`
  - **Mobile:** `.swift`, `.m`, `.dart`, `.kt`
  - **Systems:** `.c`, `.cpp`, `.h`, `.hpp`, `.rs`, `.zig`
  - **JVM:** `.java`, `.kt`, `.kts`, `.scala`, `.clj`, `.cljs`, `.groovy`
  - **.NET:** `.cs`, `.fs`, `.vb`
  - **Others:** `.lua`, `.ml`, `.hs`, `.r`, `.jl`
- Exclusion directories: `node_modules`, `.git`, `vendor`, `dist`, `build`, `.next`, `__pycache__`, `target`, `_generated`, `.turbo`, `coverage`, `.cache`
- Store CODE_FILES variable (file list) and CODE_FILE_COUNT (integer)

**Signal 2: Package Manager** — Detect package manifest presence
- Manifests to check (14+): `package.json`, `requirements.txt`, `Cargo.toml`, `go.mod`, `pyproject.toml`, `Gemfile`, `composer.json`, `*.csproj`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `mix.exs`, `pubspec.yaml`, `Package.swift`, `setup.py`, `setup.cfg`, `Pipfile`
- Store HAS_PACKAGE (first found manifest filename or empty)

**Signal 3: Git History** — Commit depth indicates project maturity
- `git rev-list --count HEAD 2>/dev/null || echo "0"`
- Store GIT_COMMIT_COUNT (integer)

**Signal 4: Directory Structure** — Complexity indicates organized project
- Count non-excluded directories
- Exclusions same as Signal 1
- Store SRC_DIR_COUNT (integer)

**Signal 5: Codebase Map** — Already analyzed
- Check: `[ -d .planning/codebase ] && echo "yes" || echo "no"`
- Store HAS_CODEBASE_MAP (yes/no)

### 3. Language Detection

Function `detect_primary_language()`:
- Count files per extension from CODE_FILES variable
- Map extensions to language names:
  - `ts,tsx` → TypeScript
  - `js,jsx` → JavaScript
  - `py` → Python
  - `go` → Go
  - `rs` → Rust
  - `java` → Java
  - `kt,kts` → Kotlin
  - `swift,m` → Swift
  - `rb` → Ruby
  - `php` → PHP
  - `c,cpp,h,hpp` → C/C++
  - `cs` → C#
  - `dart` → Dart
  - `ex,exs` → Elixir
  - `scala` → Scala
  - `clj,cljs` → Clojure
  - `zig` → Zig
  - `lua` → Lua
- Return the language with highest file count
- Store PRIMARY_LANG (language name string)

### 4. Mode Determination Logic

Decision tree (evaluated in order):
```
IF CODE_FILE_COUNT == 0 AND HAS_PACKAGE is empty:
  MODE = "greenfield"

ELIF CODE_FILE_COUNT <= 10 AND GIT_COMMIT_COUNT <= 3:
  MODE = "scaffolded"  # Graceful downgrade to greenfield

ELIF CODE_FILE_COUNT > 10 OR (HAS_PACKAGE is not empty AND GIT_COMMIT_COUNT > 10):
  MODE = "brownfield"

ELSE:
  MODE = "greenfield"  # Default safe
```

### 5. Complete Bash Script

Provide the full, copy-pasteable Bash script block that:
1. Runs all 5 signal detection checks
2. Runs language detection
3. Evaluates mode determination
4. Outputs diagnostic variables: MODE, CODE_FILE_COUNT, PRIMARY_LANG, HAS_PACKAGE, GIT_COMMIT_COUNT, SRC_DIR_COUNT, HAS_CODEBASE_MAP

### 6. Integration Guide

Explain how this module integrates with `new-project.md`:
- Replaces current Phase 1 step 3 (basic brownfield detection)
- Extends Phase 2 (Brownfield Offer) with MODE-based routing:
  - `greenfield` → proceed to Phase 3 (questioning) directly
  - `scaffolded` → inform user "This looks like a scaffolded project. Treating as greenfield." → proceed to Phase 3
  - `brownfield` → offer codebase mapping → brownfield-flow workflow
- Preserves all existing behavior for greenfield projects (regression-safe)

### 7. Testing Scenarios

List test scenarios that validate detection accuracy:
- Empty directory → greenfield
- Single `package.json`, no code files → greenfield
- `npx create-next-app` output (15+ files, 1 commit) → scaffolded
- `cargo new` output (2 files, 1 commit) → scaffolded (or greenfield)
- Mature project (50+ files, 20+ commits, package.json) → brownfield
- Python project (30+ .py files, requirements.txt, 15 commits) → brownfield
- Rust project (20+ .rs files, Cargo.toml, 10 commits) → brownfield
- Mixed language project → brownfield, PRIMARY_LANG = most common
- Already-mapped project (.planning/codebase exists) → brownfield, HAS_CODEBASE_MAP=yes

**Anti-patterns to avoid (from 01-RESEARCH.md):**
- DO NOT use binary file-existence checks only (use multi-signal scoring)
- DO NOT hardcode only JS/TS extensions (support 20+ extensions across 6 families)
- DO NOT use LLM for detection (must be deterministic Bash)
- DO NOT create a heavy script (keep under 60 lines of actual Bash)
- DO NOT forget to handle `git rev-list` failure in non-git directories
