**YAML Frontmatter:**

---

**Section-by-section requirements:**

1. **`<role>`** — State clearly:
   - You are a GSD brownfield analyzer
   - You read 7 structured codebase analysis documents (NOT raw source code)
   - You synthesize findings using the brownfield-summary template
   - You write `.planning/brownfield-analysis.md`
   - You return executive summary confirmation only
   - You are spawned by the brownfield-flow workflow after codebase mapping is complete

2. **`<why_this_matters>`** — Explain downstream consumption:
   - brownfield-flow workflow presents executive summary to user
   - User selects purpose (fix/improve/refactor) based on this analysis
   - Purpose-aware questioning references findings
   - PROJECT.md references analysis for downstream agents (planner, executor)
   - This is the compression layer: 7 docs (200-1000+ lines total) → 1 summary (~80 lines)

3. **`<philosophy>`** — Include:
   - Synthesize, don't summarize (extract patterns across documents, not per-document summaries)
   - OBSERVED vs INFERRED distinction (tag confidence levels on each finding)
   - Prioritize concerns (not all findings are equal — rank by impact)
   - Preserve file paths from source documents (actionable references)
   - Write current state only (no temporal language, no recommendations — just what IS)

4. **`<process>`** with named steps:

   `<step name="discover_documents">` — Run `ls .planning/codebase/*.md` to discover which documents exist. Expected: ARCHITECTURE.md, STACK.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, INTEGRATIONS.md, CONCERNS.md. Note which are present/missing.

   `<step name="read_all_documents">` — Read each discovered document using Read tool. For each document, extract:
   - Key findings (the most important facts)
   - File paths mentioned (preserve them)
   - Patterns/anti-patterns identified
   - Severity assessments (if in CONCERNS.md)

   `<step name="assess_health">` — Determine overall Codebase Health rating:
   - **Good:** No critical concerns, consistent patterns, test coverage exists
   - **Moderate:** Some concerns but manageable, patterns mostly consistent
   - **Concerning:** Critical issues, inconsistent patterns, low/no test coverage

   `<step name="synthesize">` — Fill the brownfield-summary template structure:
   - Executive Summary table: one-liner per dimension with confidence level
   - Top Concerns: ranked by impact from CONCERNS.md
   - 7 detailed sections: extract per the template's instructions
   - Cross-reference findings across documents (e.g., if STACK.md shows old deps and CONCERNS.md flags them)

   `<step name="write_output">` — Write `.planning/brownfield-analysis.md` using the filled template. Use Write tool.

   `<step name="return_confirmation">` — Return structured confirmation with:
   - Document written path
   - Line count
   - Executive summary table (7 rows)
   - Top 3 concerns
   - DO NOT include full document contents in return

5. **`<critical_rules>`** — MUST include:
   - **DO NOT explore the codebase directly.** Read ONLY `.planning/codebase/*.md` documents. You have Read, Write, Glob tools, but Glob is ONLY for discovering which codebase documents exist.
   - **Use the brownfield-summary template structure exactly.** Reference: `get-shit-done/templates/brownfield-summary.md`
   - **Distinguish OBSERVED facts from INFERRED assessments.** Tag each finding with confidence: HIGH (directly stated in source doc) or MEDIUM (inferred from patterns).
   - **Include file paths from source documents.** Every finding should reference specific files mentioned in the codebase docs.
   - **Return confirmation with executive summary, NOT full document contents.** The return should be ~20 lines max.
   - **DO NOT recommend fixes or improvements.** Document what IS, not what SHOULD BE. Recommendations happen in purpose-routing (Phase 3).
   - **Handle missing documents gracefully.** If fewer than 7 documents exist, note which are missing and proceed with available data.

6. **`<success_criteria>`** — Checklist:
   - [ ] All available codebase documents discovered and read
   - [ ] Missing documents noted (if any)
   - [ ] `.planning/brownfield-analysis.md` written using template structure
   - [ ] Executive Summary table has entries for all available dimensions
   - [ ] Top Concerns ranked by severity/impact
   - [ ] All findings tagged with confidence level (HIGH/MEDIUM)
   - [ ] File paths included throughout
   - [ ] Return confirmation is ~20 lines (not full document)

**Key differences from gsd-codebase-mapper (from 01-RESEARCH.md):**
- Mapper reads raw codebase files (source code, configs); Analyzer reads processed documents only
- Mapper writes per-dimension documents; Analyzer writes one synthesis document
- Mapper uses Glob/Grep/Bash for exploration; Analyzer primarily uses Read
- Mapper produces 7 documents; Analyzer consumes 7 and produces 1

**Anti-patterns to avoid (from 01-RESEARCH.md Pitfall 3):**
- DO NOT give the agent Grep/Bash tools that enable raw codebase exploration
- DO NOT let the agent re-analyze what the mapper already analyzed
- DO NOT produce an agent that returns the full 80+ line document in its confirmation
